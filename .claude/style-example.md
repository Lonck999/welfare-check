# 視覺設計參考：cofounder.co

記錄時間：2026-07-31
來源：https://cofounder.co/
用途：welfare-check 前端 UI/UX 改版的參考範本，討論用文件，**尚未定案、尚未實作**。

## 為什麼參考這個網站

使用者反饋現有網站「不太溫和親民、設計無互動感」。cofounder.co 雖然是 B2B SaaS 首頁，但它解決的正是「工具感 → 溫暖感」「靜態 → 有回饋」這兩個問題，值得抽取設計語言（不是抽取內容或產業調性）。

## 觀察到的設計語言

### 色彩
- 主背景是暖灰白 `rgb(245, 245, 242)`（不是純白 `#fff`），比較柔和，不刺眼
- 主文字色 `rgb(23, 23, 23)`（不是純黑 `#000`）
- 深色 CTA 按鈕背景接近黑但偏暖 `rgb(56, 56, 56)` 邊框色，不是死黑
- 整體是低對比、去飽和的中性色系，只有插畫（pixel art）本身帶色彩當作視覺重點，UI 元件本身克制

### 圓角
- 卡片／面板：`8px`～約 `12-16px`（大面板圓角更明顯）
- 按鈕：`8px`
- 導覽列是完整的膠囊形（pill，border-radius 接近 999px）

### 陰影（這是最值得借鏡的部分——目前 welfare-check 完全沒有陰影，是扁平的主因）
CTA 按鈕的陰影是多層疊加，不是單純 `box-shadow: 0 2px 4px rgba(0,0,0,.1)`：

```css
box-shadow:
  rgba(64, 64, 64, 0.12) 0px 0px 0px 1px,        /* 極細外框，取代生硬的 border */
  rgba(255, 255, 255, 0.24) 0px 2px 0px 0px inset, /* 內部頂端高光，模擬光源由上照下 */
  rgba(0, 0, 0, 0.25) 0px -0.5px 2px 0px inset,    /* 內部底部暗影，增加厚度感 */
  rgba(0, 0, 0, 0.03) 0px 2px 8px 0px,             /* 大範圍柔和環境陰影 */
  rgba(0, 0, 0, 0.16) 0px 3px 4px 0px;             /* 貼近物體的清晰陰影 */
```

效果：按鈕看起來像「有厚度、可以被按下去」的實體物件，而不是一塊平面色塊。這正是使用者說的「互動感」的來源之一——**在使用者做任何動作之前，靜態畫面本身就已經有立體感在暗示「這是可以互動的」**。

卡片（如 Chapter 1～4 教學卡）則是用「層疊卡片」效果做出深度：卡片背後隱約看得到另一張稍微位移、透明度較低的卡片輪廓，暗示可以左右滑動/還有更多內容，是比陰影更進一步的空間暗示手法。

### 排版
- 標題字重偏輕（`font-weight: 400`），不是粗黑體，靠字級大小（40～46px）跟留白撐出份量感，而非用粗體製造壓迫感
- 內文有明顯的字重層次：一般內文 400，強調字詞（如 feature 列表的粗體開頭字 `Agentic departments —`）用 `bold` 局部強調，不是整段加粗
- 小標籤/說明文字（如 "Chapter I"、"over 10,650 companies are running on Cofounder"）用偏小號、偏灰、有時帶等寬字體感的文字，營造「系統狀態提示」的輕量感，不搶主標題風頭

### 互動元件
- 導覽列連結：`transition: color 0.06s, font-weight 0.06s` — 極快速的顏色+字重過渡，hover 時字重從 410 變化，不是位移或縮放，細膩但存在
- 按鈕：`transition: all`（配合上面的多層陰影，暗示 hover/active 時陰影會跟著變化，做出「按下去」的視覺回饋）
- 浮動提示卡（首頁插圖上的 "● Task Completed · Marketing Campaign" 小卡片）：半透明深色底、白字、圓角膠囊，飄浮在插圖上方，是一種「輕量、非侵入式」的狀態通知手法

### 版面配置
- 大量留白（section 之間的間距非常寬鬆，不會塞滿）
- 面板（如 agent 關係圖、看板式任務卡）用大範圍淺灰底 + 圓角容器包起來，容器內部才是實際內容，形成「畫面中的畫面」層次感
- 看板卡片（Idea stage / Initial stage / Identity stage）：每張任務卡有一個彩色圓角小圖示（icon badge），搭配標題+副標題兩行文字，範例可以參考如何用小色塊圖示取代純文字列表，增加視覺掃視效率

## 第二輪：逐區塊詳細記錄（含實際互動測試）

使用者要求「重新詳細檢視這網頁的互動、樣式、排版通通記錄起來」，因此用 Playwright 完整捲動全頁（總高度 9278px）、實際觸發 hover/mousedown 等互動、並直接讀取 computed style 取得精確數值，而非只看截圖憑印象描述。以下依頁面出現順序記錄。

### 逐區塊內容與版面

1. **導覽列（sticky top）**：左側 serif 文字 logo「Cofounder」，中間是深色半透明膠囊背景包住的巢狀導覽連結（How to / Start / Build / Sell / Scale），右側獨立幾個連結（Resources / Pricing）+ 一個實心深色圓角按鈕（Run a company）。導覽列本身用小圖片當作連結間的分隔線（`/navbar/divider.png`、`divider-light.png`），不是純 CSS border。
2. **Hero**：**這裡要更正第一輪記錄的錯誤**——原本寫成「8-bit 像素風插畫」，但實際檢查 DOM 發現這其實是一段 `<video>`：`https://cofounder.co/hero/cofounder-2-hero.webm`，`autoplay` + `loop`，長度 2 秒，無縫循環播放（不是 GIF、不是 CSS 動畫，是真的影片檔）。這就是使用者問「為何這張插畫是會動的」的答案——它本來就是動態素材，只是循環得夠無縫、幀率夠低（像素風格本身格數少），乍看容易誤認成靜態插畫。畫面內容是藍天、飄動的雲、樹、草地、遠方城市天際線、一台打開的筆電＋一本筆記本，並帶有極細微的環境粒子飄動（如小光點/螢火蟲效果）。左上疊加白色大標題＋副標＋兩個按鈕（實心白底「Run a company」、半透明淺底「Check out the launch」）。插畫上方飄浮一張半透明深色圓角提示卡「● Task Completed · Marketing Campaign」，暗示「這個產品會自動完成任務」的產品敘事，用視覺而非文字傳達。
3. **Logo 牆**：4 個客戶/合作品牌 logo，各自裝在白底、細邊框、圓角的小卡片裡，下方一行小字「over 10,650 companies are running on Cofounder」（社會認同 social proof）。
4. **Agent 關係圖面板**：大範圍淺灰圓角容器，裡面是一個以「Cofounder」為圓心、8 個部門（Legal/Sales/Finance/Marketing/Support/Engineering/Operations/Design）用虛線圍成環狀關係圖的示意圖，每個節點是白底圓角小卡片；面板右側疊一個瀏覽器分頁式假 UI（Home/Company/Cofounder/Tasks/Library 分頁 + 對話輸入框）。這整塊是「產品截圖」但刻意用手繪感/簡化的方式呈現，不是真的複雜後台截圖，降低視覺負擔。
5. **教學章節卡（Chapter 1～4）**：2×2 網格，每張卡片＝白底、細邊框、圓角、陰影，內容依序是「大標題」「細分隔線」「小標籤（Chapter I，等寬小字）」「像素插畫縮圖」「作者/年份小字」。卡片背後有一張「幽靈卡片」（同形狀、些微位移、透明度較低）製造層疊/堆疊的深度感（見下方「互動測試」章節，這在 hover 時有進一步反應）。每張卡下方有獨立的「Read this chapter (N)」連結。
6. **「Build a real company」段落**：左側文案（部分文字用灰色弱化、部分黑色強調，形成漸層閱讀重點）+ 一個深色 CTA 按鈕，下方是 4 組「小圖示 + 標題 + 說明 + 兩個文字連結（Learn X / Run this in Cofounder）」＋右側對應的產品截圖假 UI（看板面板、聊天面板、Email 預覽+統計彈窗、儀表板圖表）。**版面模式很規律**：文字永遠在左、截圖永遠在右，用一條垂直細線分隔左右兩欄，4 組內容之間用大量留白隔開（不是緊湊堆疊）。
7. **「All the tools and systems」段落**：切換成全寬藍天像素插畫背景（跟 hero 呼應，首尾呼應的設計），白字大標題，下方 3 條用左側色塊短線標出重點的短文案（第一條較亮/加粗，後兩條較暗——很可能是可以透過捲動或點擊切換的分頁式重點，但本次測試沒有觸發到切換）。中間浮一張圓角白色產品截圖卡片（有分頁 tab：Enrich contacts / Research contacts / Send Outreach Emails / Campaigns）。這個藍天插畫區塊的**上下邊緣都是鋸齒狀的像素樹梢/水線**，不是矩形色塊直接切分，是像素風格特別花心思的地方。
8. **「Build across industries」文字接龍/文字搜尋方塊**：標題+說明文字之後，是一大片等寬字體的英文字母方格（實測 251 個字母格），裡面藏了很多業界關鍵詞（YOUTUBE、GROWTH AGENCY、CONSULTING、RECRUITING 等），見下方「互動測試」——這是可以互動的裝飾裝置，不只是靜態背景紋理。
9. **Footer 前導：「Run an entire company with AI agents」**：左側是次要導覽連結（How to / How to start / How to build...）+ 網站地圖式連結（Homepage/Resources/Pricing/Careers、Privacy Policy/Terms/Docs）+ 社群圖示（X、LinkedIn，各自裝在白底圓角方形按鈕裡）+ SOC 2 合規徽章＋版權/設計credit小字。右側是整個 footer 裡最搶眼的元素：一張白底圓角大卡片，上半是向日葵+蜜蜂的像素插畫，下半疊一層綠色漸層色塊覆蓋在插畫下緣，上面放最終 CTA 文案＋白底按鈕——插畫本身局部被裁切延伸出卡片邊界（葉子超出卡片右側邊框），製造「拼貼/貼紙」的手作感。
10. **最底部**：整條像素草地色帶（跟 hero 的像素天空色帶首尾呼應），中間一行小字「Made with ♥ by ...」。

### 互動測試結果（實際觸發 hover/mousedown 觀察到的行為）

- **導覽連結 hover**：字重從 410 微幅增加之外，實測發現連結底下會浮現一個**灰色圓角膠囊背景**（螢幕截圖中「Build」被 hover 後背景變成淺灰圓角矩形），不是只有文字變化，是我第一輪記錄漏掉的細節。
- **教學章節卡 hover**：卡片本身視覺沒有明顯放大/位移，但**卡片下方的「Read this chapter (I)」文字，hover 時會在文字尾端多長出一個「→」箭頭**，是很輕量、不搶戲的「可以點擊/繼續」提示，比整張卡片跳動更細膩。
- **CTA 按鈕（深色）**：預設狀態就已經有前面記錄的多層陰影（外框陰影＋內部高光＋內部暗影＋環境陰影＋清晰陰影五層疊加），`transition: all`。這次測試因為按鈕是真實連結，直接 hover+mousedown 容易觸發頁面導航，沒能穩定截到 hover 瞬間的陰影差異值——**後續在第五輪用「攔截導航」的方式重測，結果是陰影完全沒變化，原本以為會連動變化的推測是錯的，詳見下方第五輪記錄**。
- **字母方格文字遊戲（word-search）互動最有趣**：滑鼠移到任一字母上，**整列字母會從淺灰變成深黑粗體**（列高亮），且該格附近若剛好是某個被藏起來的關鍵字單詞起訖點，還會出現一條實心底線橫跨該單詞（像是「找到單詞」的視覺回饋）。這是一個藏在裝飾性背景裡的隱藏小遊戲/彩蛋，使用者不特別去滑滑鼠根本不會發現，是「探索有回饋」的最佳示範，也是這個網站互動感很強的關鍵原因之一。
- **動畫緩動曲線**：抓到一個實際存在的 transition 值 `transform 0.5s cubic-bezier(0.22, 1, 0.36, 1)`，這是一種平滑「向外緩出後穩定收尾」的曲線（視覺上比預設 `ease` 更有「回彈感」但不會真的彈跳過頭），比起隨便寫 `ease-in-out`，這種曲線更值得直接抄下來當作 welfare-check 動畫的標準緩動函式。

### 第三輪：挖出的動畫系統清單（用 `getComputedStyle().animationName` 全頁掃描找到的）

使用者追問「為何插畫是會動的」促成這輪更深入的檢查，結果發現整站有一套完整的動畫系統，遠比第一、二輪記錄的還多，列出全部找到的具名動畫：

| 動畫名稱 | 套用元素 | 時長 | 緩動 | 用途推測 |
|---|---|---|---|---|
| `hero-enter` | 首頁大標題、副標、按鈕列（各自帶 `--stagger: 0/1/2`） | 0.6s | `cubic-bezier(0.23, 1, 0.32, 1)` | **進場錯落動畫**：三塊內容不是同時出現，是靠 CSS 變數 `--stagger` 依序疊加 delay，做出「一個接一個浮現」的節奏感，而非全部同時 pop 出來 |
| `notif-slide` | 首頁插畫上飄浮的「Task Completed」提示卡外層 | 0.48s | `cubic-bezier(0.22, 1, 0.36, 1)` | 提示卡進場的位移動畫 |
| `notif-pop` | 同一張提示卡的內層 | 0.52s | `cubic-bezier(0.34, 1.56, 0.64, 1)` | 這條緩動曲線的第二個控制點 `1.56` 超過 1，代表**有輕微回彈/overshoot**（俗稱 backOut／類彈簧效果），跟 `notif-slide` 疊加使用，位移+回彈同時發生，比單純滑入更有生命力 |
| `shimmer` | 某個強調用的 `<span>`（可能是強調關鍵字或徽章） | 2.8s，**無限循環** | `ease` | 典型「skeleton loading / 高光掃過」效果，用在還沒特別去 hover 就會自己持續播放的元素上，用極低頻率的呼吸感抓住視覺餘光注意力，但不會太吵 |
| `orch-caret-blink` / `cofounder-caret-blink` | 產品截圖 mockup 裡的輸入框游標 | 0.9s／1s，無限循環，`steps(1)` | 假造「有人正在打字」的終端機游標閃爍，`steps(1)` 代表是硬切不是漸變（模擬真實文字游標的 on/off，不是霓虹燈那種淡入淡出） |
| `cofounder-pixel-refocus` | 一個 540×308 的 `<canvas 



class="cofounder-pixel-stage">`（位置對應「Scale with product analytics」段落的統計圖表區） | 1.4s | `cubic-bezier(0.16, 1, 0.3, 1)` | 圖表用 canvas 繪製＋進場時有個「對焦」動畫（推測是縮放或模糊→清晰的效果），不是單純畫一張靜態圖表截圖 |

**這輪最重要的收穫**：cofounder.co 的「動態感」不是靠一兩個 hover 效果堆出來的，而是**多層次疊加**——background 有循環播放的環境影片、進場有錯落淡入、局部元素有持續的低頻呼吸動畫（shimmer/caret blink）、互動元素有 hover 回饋、離散的資料視覺化還有進場動畫。任何單一時刻畫面上同時有好幾種不同時間尺度的動態在跑（2 秒影片循環＋2.8 秒 shimmer 循環＋0.9 秒 caret 循環＋一次性的 0.5～0.6 秒進場動畫），這種「多節奏疊加」是讓畫面感覺「活著」而不只是「有做動畫」的關鍵，跟只加一個 hover transition 是完全不同量級的工程。

### 補充：可直接沿用的具體數值

```css
/* 背景/文字色 */
--ref-bg: rgb(245, 245, 242);
--ref-text: rgb(23, 23, 23);
--ref-btn-border: rgb(56, 56, 56);

/* 按鈕/卡片標準陰影組合 */
--ref-shadow-btn:
  rgba(64, 64, 64, 0.12) 0px 0px 0px 1px,
  rgba(255, 255, 255, 0.24) 0px 2px 0px 0px inset,
  rgba(0, 0, 0, 0.25) 0px -0.5px 2px 0px inset,
  rgba(0, 0, 0, 0.03) 0px 2px 8px 0px,
  rgba(0, 0, 0, 0.16) 0px 3px 4px 0px;

/* 標準動畫緩動 */
--ref-ease: cubic-bezier(0.22, 1, 0.36, 1);
--ref-duration: 0.5s; /* 大動作（如卡片位移）；小動作（顏色變化）建議 0.06s～0.2s，抄導覽列的做法 */

/* 版面 */
--ref-container-max-width: 1100px;
--ref-container-padding: 0 24px;
--ref-base-font-size: 16px;
--ref-base-line-height: 24px; /* 剛好是 1.5 倍，跟 welfare-check 目前 style.css 的 font: 17px/150% 巧合一致，不用改 */
```

## 第四輪：手機版與遺留疑點覆核

使用者問「首頁是否已完整分析」，逐項覆核後，以下是這次補上的檢查與結論。

### 手機版（390×844 viewport 實測）
- 導覽列在手機版收合成「Run a company 按鈕 + 漢堡選單圖示（藍底圓角方形）」，不是把全部連結擠成一排小字，也不是直接消失
- Hero 影片背景等比縮放置中，文案/按鈕改直式堆疊，沒有橫向溢出（`scrollWidth - clientWidth` 實測是負值，代表完全沒有橫向捲動問題）
- 手機版漢堡選單點開後的內容：加上「攔截頁面導航」的保護後重測，成功避免被導去子頁面，但點擊命中的其實是頁面下方某個 demo 面板裡的分頁按鈕（跳出「Engineering weekly security check 2/3」這種內容），代表選到的不是真正的漢堡選單圖示，是我的按鈕選擇器（挑「沒有文字的按鈕」）不夠精準，選到了同樣是 icon-only 的其他按鈕。**這項判斷為低優先，先不繼續深究**：welfare-check 本身是單一流程的逐題問卷，不是像 cofounder.co 這種多頁行銷站需要漢堡選單收納一堆導覽連結，這個元件本身參考價值有限，不值得再花時間精確重現

## 哪些適合借用、哪些不適合

**適合直接借用到 welfare-check：**
- 暖灰白背景色（取代純白，立刻降低「冷冰冰系統」感）
- 多層陰影按鈕/卡片效果（用在「下一步」「開始查詢」按鈕、`benefit-card`、`step` 容器）
- 過渡動畫（hover/focus/active 的顏色與陰影變化）
- 圓角統一化 + 淡化邊框（邊框變細、變淺，靠陰影分隔層次而非靠邊框線）
- 小標籤文字風格（例如「第 N 題／共 N 題」進度文字可以做成更輕量的膠囊徽章）

**修正：像素/復古風格其實是系統性設計語言，不只是一張插畫**（原本這份文件在此處把它寫成「不適合借用」，判斷下得太快，記錄如下）

實際檢查渲染後發現，像素/復古終端機風格貫穿整站，不只是首頁那張插畫：
- 小標籤文字（"Chapter I"、"Idea stage"）用 **IBM Plex Mono**，字級只有 8～9px
- 統計數字（"211"）用 **departureMono**——這是專門設計成像素/復古終端機外觀的等寬字體
- 首頁 8-bit 像素風插畫、看板面板裡的點狀網格背景、"Build across industries" 區塊的字母方格紋理，都是同一套視覺語言的延伸

也就是說 cofounder.co 選的「溫度感」來源，不是「柔和圓潤」這條路線（像很多新創/消費產品那樣），而是「復古/懷舊/手作感」這條路線——像素字體跟 8-bit 插畫會讓人聯想到早期電玩、BBS 時代，帶一種「不假掰、有手感、值得信任的老派工具」的氣質，這跟单純「可愛童趣」不是同一件事。

**這件事需要跟使用者直接討論，不能我單方面決定要不要採用**，因為這牽涉到兩個方向的判斷：
- 若採用：welfare-check 會有很強烈的個性與記憶點，跟政府官方網站的制式感形成明顯差異化，可能反而讓人覺得「這是有心人做的工具」而非冷冰冰的系統
- 若不採用：維持現有較中性、資訊型的路線，改走「柔和圓角＋陰影＋動畫」但不导入像素字體/插畫，風險較低但個性也較弱

**不確定是否適合借用，需要進一步討論：**
- 大範圍留白（cofounder.co 是行銷首頁可以奢侈用留白，welfare-check 是任務導向表單，使用者要的是效率不是瀏覽體驗，留白可以增加但不能像行銷頁那樣誇張）
- 深色系導覽列（welfare-check 目前走淺色路線，貿然改深色風險較高，且不是使用者提出的問題點）
